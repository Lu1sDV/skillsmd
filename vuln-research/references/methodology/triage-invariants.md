# Triage Invariants — Cross-Target Registry

> **Load when**: Autoloaded at **Decompose** (Phase 0) and at **Confirm** (Phase 2) so every lane sees these caps inline. This is the durable, target-agnostic sink the learning loop writes back to — the place a lesson learned on one campaign survives to the next instead of dying in per-target memory.

This registry is **append-only**. Each row is a confirmed severity/triage invariant, generalized to be target-agnostic — the cited target detail is an *example*, never the rule. New invariants are added by **Phase 6 — Invariant Promotion**: for every `agent_observations(obs_kind='invariant', reusable=TRUE, confidence='high')` not already mapped to a row here, the orchestrator MUST either append a row (with the gate/doc edit and a `CHANGELOG.md` line) or record a `promotion_skipped` reason. The `v_invariant_promotion_coverage` view is HARD-RED while any high-confidence reusable invariant has neither. Never edit or delete a row — supersede it with a new `INV-id` and note the supersession in `promoted-in`.

**Generalize-then-promote.** Before appending, ask: is this invariant a special case of an agnostic rule? A lesson that *reads* target-specific (libc++, `clickhouse-client`, a particular allocator) almost always generalizes — promote the agnostic form, cite the target as evidence.
