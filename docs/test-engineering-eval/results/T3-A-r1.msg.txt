So `update_address` on a SQLite store silently wipes the order's items, which breaks the spec's \"items … left unchanged\".\n   - The returned dict still shows the items, but a later `get_order` returns `items == []`.\n   - A fix would be `UPDATE orders SET address = ?, status = ? Either keeps the row, so the cascade never fires.\n   - The docstring says `save_order` writes \"an existing order\", but the SQLite version will also silently insert an unknown one, while the in-memory version raises `KeyError`. `update_address` guards this, so it isn't reachable through that function."
