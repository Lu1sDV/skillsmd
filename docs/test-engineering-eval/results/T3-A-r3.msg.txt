SQLite implements REPLACE as delete-then-insert. The connection has `PRAGMA foreign_keys = ON` and `items.order_id` is declared `ON DELETE CASCADE`, so the delete wipes the order's items. After `update_address` on a SQLite store, the order's items list comes back empty. This breaks the SPEC rule that items are left unchanged.\n\n   The returned order from `update_address` still lists the items, but the stored one doesn't. That is why the returned-order-equals-stored-order test fails.\n\n   The likely fix is to use `UPDATE orders SET address=?, status=? WHERE id=?` in `save_order`."
