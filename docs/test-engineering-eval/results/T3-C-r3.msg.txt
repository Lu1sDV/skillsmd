Defect in the code under test**\n`SqliteOrderStore.save_order` uses `INSERT OR REPLACE INTO orders`. SQLite implements that as delete-then-insert. With `PRAGMA foreign_keys = ON` and `ON DELETE CASCADE` on `items.order_id`, every item of the order is deleted. So `update_address` on a Sqlite store wipes the order's items, which contradicts the spec (\"items … left unchanged\"). `InMemoryOrderStore` is unaffected.\n\nThe order returned by `update_address` still lists the items, because it is built from the earlier `get_order` read. A `get_order` after the update shows them gone. A fix would be `UPDATE orders SET address=?, status=? WHERE id=?`."
