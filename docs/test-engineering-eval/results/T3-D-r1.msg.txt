SQLite implements that as delete-then-insert.\n- The connection has `PRAGMA foreign_keys = ON`, and `items.order_id` is declared `ON DELETE CASCADE`. So the delete removes all of the order's items.\n- As a result, `update_address` on a SQLite-backed order silently wipes its items.\n- The fix would be to use `UPDATE orders SET address=?, status=? WHERE id=?`. That is also what the \"existing order\" docstring describes, and it would stop `save_order` from inserting a new order for an unknown id.\n- A smaller issue: `InMemoryOrderStore.save_order` raises `KeyError` for an unknown id, while the SQLite version would insert the order. The two stores behave differently there. `update_address` checks `get_order` first, so this doesn't show up through it."
