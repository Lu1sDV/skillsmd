They are marked `xfail(strict=True)`, so they will report as failures once the code is fixed and the marker should come off.\n\n3. **Defects in `src/slugify.py`:**\n   - **Non-ASCII punctuation or letters between words are dropped, not turned into a hyphen.** `.encode(\"ascii\", \"ignore\")` removes them before the regex runs. `slugify(\"foo—bar\")` gives `foobar`, and `\"a–b\"` gives `ab`. `\"a日b\"` gives `ab` and `\"a“b\"` gives `ab`. SPEC.md says each run of non-alphanumeric characters becomes one hyphen, so these should give `foo-bar`, `a-b` and so on. This is what the xfail tests cover. The fix is to replace non-ASCII characters with a separator after the NFKD step, rather than dropping them.\n   - **A negative `max_length` slices from the end.** `slugify(\"abcdef\", -1)` gives `abcde`, and `slugify(\"ab-cd\", -1)` gives `ab-c`. SPEC.md doesn't define negative values, so I didn't write a test for it. It probably should raise an error or return an empty string.\n   - **Letters with no ASCII decomposition are silently lost.** `slugify(\"Straße\")` gives `strae`. This is a limitation rather than a clear spec violation, and I did not write a test for it."
